# ChipQC Guardian：五分钟演示脚本（中文）

赛题要求公开视频不超过五分钟，且无需登录、授权或付费即可观看。下面以约 4 分 45 秒为目标。所有屏幕录制使用真实运行的本地应用、真实来源且获准展示的图像；不能用静态原型冒充模型推理。

| 时间 | 画面与操作 | 建议配音 |
| --- | --- | --- |
| 0:00–0:25 | 标题，随后展示 OoC 芯片/明场图像来源说明和数据 DOI。 | “器官芯片实验会持续产生明场图像。研究人员需要判断样本状态是否适合继续分析，但逐张人工检查耗时，也容易受采集质量影响。ChipQC Guardian 希望让人工复核更聚焦。” |
| 0:25–0:55 | 在真实应用中打开一张有权限展示的 OoC 图像；再切到原始数据表或数据审计图显示其细胞系和元数据。当前应用本身不显示这些元数据。 | “我们使用公开的器官芯片图像数据。原始表格有三千零七十二条记录，覆盖六种细胞系。上游由生物学专家标注样本质量。这里显示的是具体图像及其来源，而不是合成示例。” |
| 0:55–1:30 | 展示数据审计画面或报告图：59 个日期样式前缀、整组划分、标签映射的来源示例。 | “相邻图像可能来自同一天的采集。我们用文件名中的日期样式前缀分组，把同组图像放在同一个训练、验证或测试集合，避免看起来很高的随机切分成绩。数字标签一与二，也先和官方归档路径交叉核对为 good 与 bad。” |
| 1:30–2:20 | 实际点击或拖入图像；展示可读性指标、模型可用状态、概率或明确的‘未训练’状态。若已有训练产物，显示其哈希/版本。 | “系统先检查图像能否解码，再计算可解释的亮度、对比度、边缘和清晰度指标。若已加载经过验证的模型，才展示模型评分；若没有模型，界面明确说未训练，不会把演示规则当作预测准确率。” |
| 2:20–3:05 | 依次演示 PASS、REVIEW、REACQUIRE；用真实图像和真实触发理由。对 REACQUIRE 展示采集质量触发，不把 bad 样本简单说成应重拍。 | “三种建议各有边界：PASS 是在已验证阈值内可继续人工确认；REVIEW 把不确定或超出适用范围的图像交给研究人员；REACQUIRE 指向文件损坏或图像采集问题，或者由研究人员确认需要重新成像。专家所说的生物学低质量，并不一定能靠重拍解决。” |
| 3:05–3:55 | 展示 `reports/vision_evaluation.json`、12 组/670 张的测试集、混淆矩阵和组 bootstrap 区间。 | “我们在十二个从未参与训练和选模的日期前缀组、六百七十张图像上测试。模型准确率是 0.718，平衡准确率 0.712，AUROC 0.772；但完整组重采样区间很宽。校准集也没有阈值达到我们预设的安全自动 PASS 标准，所以系统不把概率包装成自动放行。” |
| 3:55–4:25 | 展示一例失败案例或复核覆盖、六细胞系分层表；必要时遮去没有使用权的图像。 | “整体分数可能掩盖小样本细胞系的弱点。我们按细胞系查看错误，并保留原图让研究人员解释、纠正建议。模型不判断药效、疾病或组织活性。” |
| 4:25–4:45 | 展示公开仓库、报告、数据 DOI、可复现命令；最后定格项目名称。 | “代码、实验协议和局限会随报告公开。源图像仍由原始数据集管理；本项目提供可复现的质量控制流程和清楚的人机分工。” |

## 拍摄前核对

1. 用已完成、校验通过的原始图像归档运行真实应用；核对屏幕上的标签映射、分组和模型状态。
2. 若展示数值，记录模型文件哈希、分组清单哈希、评估文件路径和实际运行日期；配音中的数字与报告逐项一致。
3. 用至少一例 REVIEW 和一例确属采集问题的 REACQUIRE 演示解释文字。没有这类真实案例时，把该段改为界面规则说明，不伪造一次命中。
4. 视频原图、缩略图、背景音乐和图标都要核对许可；公开播放链接用无痕窗口验证无需登录。
5. 导出成片后完整播放，确认时长≤5分钟、字幕可读、声音清楚；如报告尚无已验证指标，删掉 3:05–3:55 的成绩播报并明确未完成状态。
